How to use this guide

Part 1 explained every concept of the prototype from zero: what an LLM is, RAG, chunking, embeddings, vector stores, BM25, Reciprocal Rank Fusion, prompting, follow-up questions, citations, LangGraph and evaluation. This guide assumes you know those ideas. It explains only what is new or different in the production system, in the same way: plain language first, then the precise idea, then the exact place in the code.

The same five boxes appear again:

How to explain it in an interview, in two or three sentences.

Pitfall

A mistake that was actually made or measured along the way, or a limitation to know.

One habit runs through the whole guide: every important choice was measured before it was kept. Several plans did not survive the measurement: the reranker, hybrid search as the default, a single relevance threshold and the Hugging Face demo. Where that happened, the guide shows the plan, the number and the change. Those reversals are the most valuable part to understand and to talk about.

Reading order. Read the one-page overview next, then Parts A to D in order (each builds on the previous one). Parts E to G can be read in any order. Part H and the appendices are for revision.

The production system in one page

The goal. Turn the case-study prototype (six text files, a local chatbot, a 44-question evaluation) into a system a car maker could run: several markets and languages, real document formats, live data, human handoff, an API, a web app, safety, monitoring, automatic quality checks and a deployment, all on free software.
